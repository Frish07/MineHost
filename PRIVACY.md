# Privacy policy

MineHost stores server profiles, worlds, logs, settings, backups and managed Java runtimes on the user's computer. MineHost has no analytics, advertising, telemetry endpoint, developer account login or uploads without explicit action or an approved backup schedule.

Network access initiated by MineHost follows explicit user actions or an approved Google backup schedule:

- Loading Minecraft versions and installing Paper contact the official PaperMC download service. The service receives the requested version/download URL, IP address and the MineHost User-Agent.
- Selecting Vanilla, Purpur or Fabric contacts Mojang's official manifests/downloads, the Purpur API, or Fabric Meta respectively. Installing Fabric also allows its launcher, after the user starts Java, to fetch official libraries and Minecraft files.
- Searching Modrinth sends the entered search text, loader/Minecraft filters, sort order and page offset to its public API. Opening versions and installing addons sends project/version requests and downloads JARs from the official Modrinth CDN. The service receives network metadata and the MineHost User-Agent. Installed files and server logs are not uploaded to Modrinth. See [Modrinth privacy](https://modrinth.com/legal/privacy).
- Downloading Java, after consent, contacts the Adoptium API and its GitHub-hosted Temurin releases. These providers receive the request and network metadata. Merely detecting an installed Java runtime is local.
- Starting a Minecraft server launches a separate Java process. Minecraft/Paper may contact their authentication or dependency services; third-party plugins may make their own requests. MineHost does not sandbox plugin network access. The user chooses whether to run these programs.

Windows WebView2 and Windows security/update services are Microsoft components with their own privacy behavior.

The file/world managers operate locally. World archives remain local unless explicitly selected for Google backup or an approved cloud schedule. The player manager reads Minecraft's local lists and sends administrative commands to the local Java process. Minecraft may contact its account services when resolving player names. The online list is a manual snapshot, not telemetry; MineHost does not send player lists to its developer.

Provider information: [PaperMC](https://papermc.io/), [Eclipse Foundation privacy](https://www.eclipse.org/legal/privacy.php), [GitHub privacy](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement), [Microsoft privacy](https://privacy.microsoft.com/privacystatement). No API-specific privacy-policy URL for the PaperMC download service has been verified; the MineHost request behavior is described above.

The optional code-signing pipeline transfers public build artifacts and build provenance from GitHub Actions to SignPath. This happens on GitHub runners; no end-user server directories, logs or personal Minecraft data are submitted. See [SignPath privacy](https://signpath.io/privacy-policy).

In 0.4.0 Forge/NeoForge metadata and installer downloads contact their official Maven servers. With explicit consent MineHost runs the verified installer in a separate Java process; that installer contacts its official dependency sources. Local .mrpack imports download approved files from the Modrinth CDN, GitHub/raw.githubusercontent.com or GitLab using hashes recorded in the pack. Gallery images are fetched from the Modrinth CDN when a project is opened. Connection events observed in local server logs are retained locally in SQLite, up to 10,000 events per profile, and are not uploaded. Dimension transfers and backup restoration remain local.

0.5.0 networking: only on explicit actions, ipify receives a request to discover the public IPv4, and api.mcsrvstat.us receives the chosen public server address for an external status check (the provider caches results for up to five minutes). Windows DNS diagnostics use the configured system DNS servers. Adapter inspection is local. Firewall and UPnP changes require separate consent; Windows UAC authorizes firewall changes. The optional official playit agent contacts playit infrastructure and forwards the tunnels assigned to that agent after explicit start consent. Browser claim uses the official playit API. The key is stored with Windows Credential Manager and is not sent to React, SQLite or the MineHost developer. A short-lived provider config/log directory has a protected Windows ACL and is removed on managed-agent stop; its process is attached to a kill-on-close Job Object. No service or autostart is installed. Local network preferences contain hostnames, ports and addresses, but no authentication keys. Choosing a different connection preference does not automatically remove router/firewall rules or stop an independently configured tunnel.

0.6.0 Google Drive: consented browser OAuth uses only drive.file. Google receives the account authorization, uploaded complete profile ZIPs, backup metadata/checksums and network metadata. Archives may include player lists, server configuration and third-party files; they are not additionally encrypted. Client configuration, refresh tokens and upload-session URLs are stored in Windows Credential Manager, never SQLite, React or developer telemetry. Access tokens exist in backend memory. The temporary callback listens only on loopback. Approved schedules can upload while MineHost is open and the server is stopped, and remove only automatic copies under the selected retention; cloud copies move to Trash. Disconnect/revoke and local forget are distinct actions. No Google account credentials or authenticated backups are submitted by CI. See [Google privacy](https://policies.google.com/privacy), [setup and limits](docs/GOOGLE_DRIVE.md).

0.7.0 monitoring reads owned Java process counters locally only while the monitoring page is visible. Tick metrics use an explicit spark tps console command; no profiler upload or plugin installation is initiated. Restart policy is opt-in, stored locally and may execute the same server code again after a crash. No servers are auto-started on application launch. Process metrics and restart state are not sent to the developer or cloud.
