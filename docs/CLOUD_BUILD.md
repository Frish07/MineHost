# Облачная сборка без локальной среды

## Настройки GitHub

Нужны репозиторий `Frish07/MineHost`, включённые Actions и доступ к Windows runners. В Settings → Actions → General разрешите GitHub Actions создавать коммиты (`Read and write permissions`). Prepare использует собственный явно ограниченный `GITHUB_TOKEN` с `contents: write` и `actions: write`. Если правила организации или защита main запрещают bot push, получите lock-файлы из artifact `cloud-lockfiles`, добавьте их через интерфейс GitHub и запустите Build вручную. Никаких PAT в исходниках или пользовательских инструментах не требуется.

Prepare автоматически запускается при изменениях manifest/toolchain и доступен вручную в Actions. Он разрешает транзитивные версии, сохраняет lock-файлы и нормализует Rust через cargo fmt **на runner**. Перед release просмотрите commit зависимостей. Изменения версий делаются через manifest и новый запуск Prepare. Lock-файлы нельзя сочинять вручную.

## Проверка

Actions → Build Windows x64 → Run workflow → main. Дождитесь всех проверок. Внизу успешного запуска скачайте `MineHost-windows-x64`. В ZIP должны быть основной EXE, `*-setup.exe`, `SHA256SUMS.txt`, README и LICENSE. При отсутствии этих файлов сборка не считается готовой.

Workflow устанавливает Node 22.14.0, использует Rust 1.91.1 с rustfmt/clippy, MSVC из windows-latest и NSIS через Tauri bundler. Всё это существует только внутри виртуальной машины Actions. Java для компиляции MineHost не нужна. npm кэшируется по package-lock, Cargo — по toolchain/Cargo.lock/manifest; сохранение артефактов — 30 дней.

## Релиз без локального Git

После успешного Build запустите **Create version tag** в Actions. Укажите `v0.1.0` (или измените одновременно package.json, Cargo.toml и tauri.conf.json перед новой версией). Workflow проверяет успешную сборку точного main commit, создаёт тег и явно запускает release workflow: теги от GITHUB_TOKEN сами по себе не запускают новые workflow. Release также поддерживает обычные push тегов от пользователя.

Release собирает именно tagged commit, проверяет версии, повторяет проверки, скачивает artifact этого же запуска, проверяет хеши, создаёт черновик и публикует его после загрузки файлов. Публикация существующего релиза не перезаписывается. При сбое после создания draft удалите незавершённый draft через GitHub и повторите неуспешные jobs. Релиз с ошибкой сборки опубликован не будет.

Сборки не подписаны. Для подписи издателем потребуется отдельный сертификат и secrets Actions; сертификат и пароль нельзя добавлять в репозиторий. В будущем можно добавить подписывание без установки инструментов у пользователя.

## Разбор ошибок

Откройте красный job, раскройте первый неуспешный шаг. Исправляйте исходники в репозитории и повторяйте Actions. Для форматирования запустите Prepare, затем проверьте новый Build. Не запускайте Cargo/npm на пользовательском компьютере. При недоступности Actions не объявляйте сборку готовой: зафиксируйте причину и дождитесь реальных артефактов.
