# Архитектура

Один Tauri WebView2 frontend обслуживает все профили. React вызывает именованные Rust-команды: frontend не получает shell или общий файловый доступ. Capabilities дают только подписку на события и выбор JAR. CSP запрещает внешний контент и удалённые скрипты. Все API-запросы идут из Rust по HTTPS.

SQLite хранит UUID, выделенный порт и JSON профиля; уникальный индекс предотвращает конфликт между профилями. Файлы сервера лежат под UUID в пользовательском LocalAppData. Mutex сериализует изменения состояния; маркер операции блокирует одновременный запуск, импорт, скачивание и удаление одного профиля. Java runtime обновляется только без работающих серверов и других операций.

Paper adapter получает версии и только STABLE сборки через Fill v3; версия Java берётся из метаданных выбранной версии Minecraft. Загрузка стримится в уникальный временный файл, имеет лимит размера и проверяется SHA-256 перед переименованием. Adoptium adapter выбирает Windows x64 JRE нужного major, проверяет SHA-256, безопасно извлекает ZIP в staging, проверяет java -version и переносит в приватный runtimes. Он не запускает установщики Java и не меняет окружение Windows.

Каждый Minecraft запускается как отдельный дочерний процесс Java через Command и массив аргументов; shell не используется. Отдельные reader threads читают stdout/stderr, ограничивают строки 8 KiB и буфер 2000 записей на профиль. Поток ожидания регистрирует настоящий код выхода. Stop пишет только stop в stdin. Выход приложения блокируется при активных процессах и операциях; сначала пользователь останавливает серверы.

JAR не исполняется MineHost; проверка manifest — фильтр формата, не sandbox и не проверка совместимости. Распаковка runtime запрещает path traversal, абсолютные пути, ADS, symlink; проверка reparse points защищает операции с файлами от обычных junction. Это не защита от атакующего процесса того же пользователя, одновременно меняющего файловую систему. Properties сохраняются с резервной копией и атомарной заменой; сохраняется выделенный порт и online-mode=true. Архив backup создаётся только после остановки Java.

Следующие адаптеры (SoftwareProvider, AddonProvider, TunnelProvider, BackupProvider) нужно выделять по мере появления второй реальной реализации; неиспользуемые интерфейсы с фиктивными ответами не включены. Google Drive потребует отдельной OAuth-конфигурации разработчика, loopback callback с PKCE, scope drive.file и Windows Credential Manager. Текущая версия не запрашивает учётные данные Google.

В 0.2.0 `software::Software` задаёт интерфейс получения версий, установки, выбора launcher и допустимых загрузчиков дополнений. Serde default сохраняет чтение старых Paper-профилей. Vanilla использует официальный Mojang manifest и SHA-1, Purpur — v2 API и MD5, Fabric — stable loader/installer из Fabric Meta и отдельный launcher. JSON API кэшируются на 120 секунд с ограничением 128 записей и 16 МиБ входных JSON; ответ ограничен 4 МиБ.

`modrinth` получает реальные проекты и версии через API v2, ограничивает требуемые зависимости 32 проектами и 16 уровнями, проверяет loader/game-version/server-side, конфликты версий и явные incompatibilities. Перед установкой frontend подтверждает полный набор version IDs; backend заново вычисляет план и сверяет его, не доверяя URL или хешам из frontend. `addons` скачивает JAR по SHA-512 в staging, проверяет формат и только затем меняет файлы с резервными копиями и откатом. Каталог Vanilla заблокирован. Манипуляции с файлами выполняются только при остановленном сервере. Это не полный solver обратных зависимостей уже установленного набора.

В 0.3.0 `files` ограничивает относительные пути компонентами Windows, запрещает private `.minehost` и reparse points, редактирует только текстовые форматы до 1 МиБ. SHA-256 ревизии предотвращает незаметную перезапись изменённого файла. Изменения выполняются через `profile_task` на blocking worker с общим `Operation`, исключающим одновременный запуск сервера.

`worlds` сначала проверяет весь ZIP, затем распаковывает в уникальный staging и переносит готовую папку без замены существующих миров. Проверяются Windows-имена, ссылки, коллизии путей, размер, глубина и число записей; архив не исполняется. Экспорт потоковый, работает только после остановки сервера. Новый мир — настройки и пустая папка до следующего запуска Minecraft, а не фиктивно сгенерированные данные.

`players` читает ограниченные JSON-списки Minecraft. Фиксированные административные действия принимают только валидный ник; свободный текст разрешён только для `say` с запретом управляющих символов. Запрос онлайн имеет уникальный token сессии и timeout 10 секунд; стандартная строка `list` попадает в ответ только при активном запросе. Отсутствие ответа не превращается в нулевой онлайн. Автоматического опроса системы нет.

0.4.0: `archive` performs bounded path validation, staged extraction and overlay rollback. `forge` resolves official Maven builds, verifies installer checksums and its Minecraft target, runs only the explicit Java installer, then launches the server using its validated Windows argument-file path. Batch files and user_jvm_args are not invoked. `modpacks` verifies exact loader/game dependencies and SHA-512, excludes client-only files, applies server-overrides last and commits only after all checks. `backups` includes profile metadata, creates safety copies and swaps directories with rollback while retaining port/authentication/EULA policy. `dimensions` holds operation guards for both stopped profiles and handles vanilla/Paper layouts without converting Minecraft versions. `history` records standard observed join/leave messages in bounded SQLite storage, distinct from cached players. Catalog images are restricted to validated PNG/JPEG/WebP returned as data URLs; project Markdown is displayed as text.
