# Этапы и проверка готовности

- Этап 1: Paper, профили SQLite, загрузка, Java, EULA, процессы, консоль, stop, properties. Версии 0.1.x прошли облачные проверки; 24 ноября 2026 владелец сообщил, что вручную проверил все доступные функции и они работают.
- Дополнения к основе: импорт Paper plugin JAR с согласием и резервной копией, локальный ZIP backup остановленного сервера.
- Этап 2A / 0.2.0: Vanilla/Purpur/Fabric adapters, Modrinth и обязательные зависимости, импорт и менеджер установленных JAR, обновления/включение/отключение/удаление, резервные файлы и откат замены. Новые функции проверяются отдельными тестами в Actions; ручную проверку 0.2.0 не следует считать выполненной на основании тестов 0.1.x.
- Этап 2B, первая часть / 0.3.0: файловый менеджер и текстовый редактор с проверкой изменений и резервными копиями; выбор/подготовка/импорт/экспорт миров; списки игроков, онлайн через `list`, whitelist/OP/ban/kick/say через консоль. Проверки выполняются в GitHub Actions; ручное тестирование 0.3.0 ещё требуется.
- Этап 2B / 0.4.0: реализованы Forge/NeoForge installers и launch adapters, галереи/категории Modrinth, импорт .mrpack, история join/leave, перенос стандартных Nether/End между совместимыми профилями, полное/помировое восстановление с защитной копией. Требуются облачные проверки и ручной тест новых сценариев; ограничения форматов перечислены в README. CurseForge ZIP, Quilt и произвольные модовые измерения не заявляются поддержанными.
- Этап 3 / 0.5.0: официальный standalone playit 2.0.2 с согласием, browser claim + Windows Credential Manager, IPC статуса и адресов; ручные туннели, локальная/внешняя диагностика Minecraft, сравнение WAN/публичного IPv4 для CGNAT, A/AAAA/SRV, отдельные подтверждения firewall/UAC и UPnP. Реализовано в коде; автоматические проверки выполняются в Actions. Реальная привязка аккаунта, создание публичного туннеля, UAC и роутер требуют ручной проверки владельцем. Собственные домены playit — официальная платная функция, а не бесплатный обход через DNS.
- Этап 4 / 0.6.0: реализованы Desktop OAuth PKCE + drive.file, Credential Manager, resumable uploads с прогрессом/паузой/продолжением, проверенное скачивание для восстановления, retention и планировщик остановленных профилей при открытом MineHost. Никаких токенов в SQLite. Требуется собственный Google Desktop OAuth-клиент; реальная авторизация, загрузка/возобновление и восстановление в аккаунте требуют ручной приёмки владельцем. [Настройка](GOOGLE_DRIVE.md).
- Этап 5A / 0.7.0: реализованы CPU/RAM Windows, суммарные счётчики, uptime, ручной spark TPS/MSPT, ручной перезапуск и ограниченная политика автовосстановления. Требуются Actions и ручные игровые сценарии из [MONITORING](MONITORING.md).
- Этап 5B: CurseForge при разрешённом API/ключе, форма основных server.properties, согласованные копии работающего сервера, подпись (после окончания разработки) и usability/оптимизация.

## Обязательный smoke test на Windows 11

Скачать release, сверить checksum, установить и запустить без Rust/Node/Visual Studio. Создать два профиля с разными портами. Скачать стабильный Paper. Подтвердить EULA вручную, обнаружить или с согласием загрузить JRE. Запустить и дождаться Done. Подключиться Minecraft-клиентом; проверить `list`/`say` в консоли. Остановить и дождаться выхода. Установить доверенный plugin JAR. Проверить backup ZIP и его содержимое. Запустить второй профиль независимо. Проверить запрет конфликта портов, ошибки несовместимой Java, блокировку закрытия с живым сервером и сохранение профилей после перезапуска приложения.

Успешная компиляция не заменяет этот smoke test. Не отмечать эти шаги выполненными без реального запуска.
