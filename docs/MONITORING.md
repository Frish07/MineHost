# Мониторинг и перезапуск — 0.7.0

## Реальные счётчики

Раздел «Мониторинг» читает GetProcessTimes и GetProcessMemoryInfo по дубликату дескриптора Java-процесса, запущенного MineHost. PID используется для отображения, а не для поиска чужого процесса. CPU — изменение user + kernel time между замерами, нормализованное на число активных логических процессоров всего ПК: 100% означает всю вычислительную мощность. Первый замер не показывает выдуманный ноль. Запросы чаще 900 ms используют предыдущий замер.

Working set — физически резидентные страницы процесса, включая общие. Private commit — приватная выделенная память, которая может быть выгружена. Суммы рабочих наборов не равны уникальной физической RAM: общие страницы могут учитываться несколько раз. Heap / 12 GiB — существующий предел суммы Xmx, а не реальное потребление Windows; JVM использует и другую память. GlobalMemoryStatusEx даёт общую/доступную физическую память ПК. Ошибка счётчика отображается явно, суммы помечаются неполными. Дочерние процессы модов/плагинов отдельно не включаются.

Сбор выполняется только при открытом разделе и видимой странице, раз в 1.5 секунды. Нет постоянного системного опроса, выгрузки метрик или хранения истории в облаке. Время работы относится к текущему Java-процессу и сбрасывается при повторном запуске. Наличие процесса не доказывает готовность Minecraft: дождитесь Done в консоли. Число join/leave отражает только распознанные стандартные сообщения; точный снимок ответа `list` запрашивается в «Игроках».

Источники: [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes), [Windows memory counters](https://learn.microsoft.com/en-us/windows/win32/memory/memory-performance-information).

## TPS / MSPT

Кнопка запрашивает документированную команду `spark tps` через stdin того же Java-процесса. Требуется совместимый встроенный или установленный spark. MineHost не устанавливает plugin/mod автоматически. Запросы ограничены одним за 10 секунд на профиль; тайм-аут — 10 секунд. Без ответа или при изменённом/локализованном формате интерфейс сообщает недоступность вместо вычисления TPS из загрузки CPU.

TPS показывается для окон 5s, 10s, 1m, 5m, 15m. MSPT — min, **median**, p95, max за последние 10s; медиана не называется средним. Если spark не предоставляет длительности тика, MSPT остаётся неизвестным. Запросы привязаны к сессии Java; ответ прежнего процесса не подставляется новому. Изменяющие вывод плагины могут сделать парсер несовместимым; консоль сохраняет исходные сообщения.

Источники: [spark TPS/MSPT](https://spark.lucko.me/docs/guides/TPS-and-MSPT), [официальный формат команды](https://github.com/lucko/spark/blob/master/spark-common/src/main/java/me/lucko/spark/common/command/modules/HealthModule.java), [Paper performance commands](https://docs.papermc.io/paper/reference/commands/).

## Ручной и автоматический перезапуск

«Перезапустить» отправляет `stop`, ждёт реального завершения текущей Java и ограниченного завершения чтения stdout/stderr, затем заново проверяет EULA, установленное ядро, Java, порт и общий heap. Второй процесс не запускается параллельно первому. Принудительного завершения по таймеру нет. Если Java не завершает stop, это видно в статусе; можно отменить запланированный повтор, но отмена не откатывает уже отправленный stop.

Автовосстановление по умолчанию выключено. Настройки каждого профиля сохраняются отдельно в SQLite:

- 1–10 попыток в серии;
- начальная задержка 5–300 секунд, удвоение до максимума 300 секунд;
- сброс серии после 60–86400 секунд стабильного времени работы процесса.

Включение требует согласия на повторное исполнение Java, модов и плагинов. Без ручного намерения остановить процесс подтверждённый ненулевой код выхода считается сбоем. Ошибка ожидания не разрешает запуск второго процесса: MineHost продолжает ждать подтверждения выхода Java. Ручной Stop и команда `stop`/`minecraft:stop` не запускают восстановление. Чистый exit 0 не считается аварией. Проверка того, что Minecraft достиг Done, не подменяется временем жизни процесса.

Ручной Start и Restart сбрасывают серию. Успешный автоматический запуск сохраняет счётчик до стабильного периода; повторный быстрый сбой исчерпывает лимит. Ошибка подготовки повторного запуска прекращает серию и показывается пользователю. Политика не запускает сервер при открытии MineHost. Ожидающие задания не переживают выход из приложения; сначала отмените их в мониторинге. Во время ожидания заблокированы изменения профиля, его резервирование и выход; отмена освобождает блокировку после подтверждения worker. Политика хранится отдельно от миров и не восстанавливается из ZIP.

## Проверка на Windows 11

В Actions проверяются реальные Windows-счётчики дочернего процесса, расчёт CPU, лимит/задержка/отмена повторов и формат spark. Владелец должен дополнительно проверить: Paper с Done, несколько одновременно работающих серверов, остановку и ручной повтор, аварийное завершение Java с включённой/выключенной политикой, исчерпание лимита, отмену во время задержки, освобождение порта, сохранение миров и совместимость spark на выбранных ядрах. Успешная сборка сама по себе не подтверждает эти игровые сценарии.
