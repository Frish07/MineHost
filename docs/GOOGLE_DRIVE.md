# Google Drive: настройка и проверка

MineHost 0.6.0 использует Google Drive API v3, Desktop OAuth с PKCE (S256), системный браузер и временный callback только на `127.0.0.1`. Запрашивается только `https://www.googleapis.com/auth/drive.file`. Пароль Google в приложение не вводится. Rust, Node.js, JDK и инструменты сборки для настройки не нужны.

## Первая настройка

В этой версии общий опубликованный OAuth-клиент разработчика не включён. До создания собственного клиента вход в Google недоступен — это реальная внешняя настройка, а не ошибка установки. Файл клиента не является токеном доступа к аккаунту.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), выберите или создайте свой проект.
2. Включите [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com).
3. Настройте Google Auth Platform: Branding, Audience и Data Access. Укажите имя приложения, свой контактный email и scope `drive.file`. Если выбран External / Testing, добавьте свой Google-аккаунт в Test users. Не публикуйте приложение для других пользователей до выполнения требований Google.
4. На странице Clients создайте OAuth client ID **Desktop app**. Web application и service account не подходят. Скачайте JSON клиента с объектом `installed`. Фиксированный localhost-порт и ручной OOB-код не нужны.
5. В MineHost откройте «Резервные копии» → «Настроить OAuth (JSON)», выберите этот JSON. Параметры клиента сохранятся в Windows Credential Manager. MineHost игнорирует адреса API из JSON и использует только фиксированные официальные Google endpoints.
6. Нажмите «Войти через Google», подтвердите запрос приложения, завершите вход в системном браузере и вернитесь в MineHost. Окно ожидания действует три минуты, его можно отменить.

Desktop apps являются публичными OAuth-клиентами: их client secret не эквивалентен серверному секрету. Тем не менее MineHost не пишет параметры клиента или токены в SQLite, логи, React либо Git. JSON не нужно отправлять в чат или коммитить в репозиторий. Исходный скачанный JSON остаётся там, куда вы его сохранили; MineHost его не удаляет.

Политики Google Workspace, отключённый API, квота, настройки consent screen и режим Testing могут ограничивать авторизацию и срок жизни refresh token. При отказе/истечении токена войдите повторно; приложение не обходит ограничения Google. [Правила OAuth](https://developers.google.com/identity/protocols/oauth2), [Desktop flow](https://developers.google.com/identity/protocols/oauth2/native-app), [scope drive.file](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

## Загрузка и восстановление

Остановите сервер, создайте локальную ZIP-копию, выберите её и подтвердите загрузку. Весь профиль, включая миры, настройки, списки игроков, моды и плагины, отправляется в ваш Drive. Дополнительного шифрования ZIP нет; квота Google Drive расходуется по правилам вашего аккаунта.

Загрузка выполняется чанками до 8 MiB через resumable API. Шкала показывает подтверждённые Google байты, а не только отправленные. При сетевой ошибке приложение опрашивает состояние сессии и повторяет оставшиеся данные с ограничением числа попыток. Кнопка паузы проверяется между этапами и запросами; создание ZIP и уже выполняющийся запрос могут завершиться не сразу. Сессия хранится в Windows Credential Manager; после перезапуска MineHost можно продолжить загрузку того же неизменённого ZIP. Истёкшую сессию нужно явно забыть и начать заново. При смене локального файла возобновление отклоняется.

После завершения проверяются размер и MD5 из Google Drive; SHA-256 записывается в appProperties. Скачивание проверяет размер, MD5 и SHA-256, безопасную структуру ZIP и совместимость ядра/Minecraft. Проверенные файлы попадают в локальный список текущего профиля. Нажмите «Просмотреть и восстановить» ниже, выберите весь сервер или мир и подтвердите замену. Перед заменой создаётся защитная копия. Моды и плагины внутри архива требуют доверия владельца; хеш не является антивирусом или подписью автора.

Список показывает MineHost-копии всех профилей, доступные тому же OAuth-проекту. Для восстановления на другом ПК импортируйте тот же Desktop client JSON, войдите в тот же Google-аккаунт и создайте профиль с совместимым ядром и версией Minecraft; UUID целевого профиля может отличаться. Другой OAuth-проект может не видеть прежние приватные appProperties/файлы. Произвольные файлы всего Drive не перечисляются. Копии создаются в корне My Drive и помечаются appProperties; общий доступ автоматически не включается. Shared Drives в этом этапе не поддерживаются.

## Расписание и очистка

Для каждого профиля задаются интервал 1–168 часов, хранение 1–100 локальных автоматических копий и необязательная загрузка/хранение в Drive. Включение требует отдельного согласия. Планировщик работает только при открытом MineHost, раз в 30 секунд проверяет срок, ждёт остановки сервера и завершения конкурирующих операций. Сам Java не останавливает и не запускает. Просроченный срок запускается один раз, следующая дата считается от успешного выполнения. Ошибка отображается в расписании, повтор — не чаще одного раза в пять минут.

Локальная очистка затрагивает только `UUID-auto-UUID.zip` этого профиля после создания новой локальной копии. Ручные и защитные копии сохраняются. Облачная очистка касается только помеченных `kind=scheduled` копий того же профиля после успешной загрузки; старые копии перемещаются в корзину, а не безвозвратно удаляются. Корзина может продолжать занимать квоту. Пауза другой загрузки блокирует новую облачную задачу до возобновления или явного отказа от сессии. При удалении профиля расписание удаляется; локальные/облачные архивы автоматически не удаляются.

«Отключить и отозвать доступ» обращается к Google revoke endpoint и удаляет локальный refresh token. Если сеть недоступна, можно отдельно выбрать «Забыть локально», затем отозвать доступ в настройках Google-аккаунта. Облачные копии сохраняются. Для изменения OAuth-клиента сначала отключитесь.

## Что проверяется автоматически

GitHub Actions проверяет PKCE по RFC-вектору, state/Host callback, реальную передачу по локальному HTTP fixture с ошибкой 503 и возобновлением от подтверждённого Range, отмену и защиту ручных копий от retention. Это проверки протокола и кода; они не означают успешный вход в реальный Google-аккаунт. Авторизация, квота, загрузка большого мира, повтор после перезапуска и восстановление с вашим OAuth-проектом требуют ручного теста владельца. В CI пользовательские Google-токены не передаются.
