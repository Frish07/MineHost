# MineHost

## Мониторинг и перезапуск — 0.7.0

Реальные Windows-счётчики CPU/RAM Java-процессов, общая память и uptime; ручной TPS/MSPT через совместимый spark; корректный перезапуск через stop и ограниченное автовосстановление после сбоя с явным согласием. Добавлены фильтры уровней консоли. [Семантика счётчиков, ограничения и проверка](docs/MONITORING.md). Автоповтор по умолчанию выключен; процесс не запускается при открытии MineHost.

Реальный вход и работу с аккаунтом проверяет владелец; успешная сборка не заменяет этот тест.

## Обновление 0.7.0 — подключения и сеть

- **playit.gg**: официальный standalone `playitd` 2.0.2, закреплённый URL и SHA-256. Загрузка или копирование существующего именно этого бинарного файла требуют согласия. Служба Windows и автозапуск не устанавливаются; существующая системная служба playit не изменяется. Для неё можно использовать ручной режим подключения.
- Привязка через официальный браузерный claim-flow. Ключ хранится в **Windows Credential Manager**, не в SQLite и не в React. При запуске он передаётся агенту по локальному IPC с проверкой PID процесса. Временный файл самого агента находится в каталоге с защищённым Windows ACL и удаляется при остановке. Job Object завершает управляемый агент при аварийном выходе MineHost. Обычный выход блокируется до остановки серверов и агента.
- Один агент обслуживает все назначенные ему туннели. Создайте в кабинете playit Minecraft Java TCP-туннель на `127.0.0.1:<порт профиля>`. MineHost показывает реальные адреса из IPC, состояние агента и соответствие локальному порту; неподходящий туннель не используется для внешней проверки. Состояние обновляется раз в пять секунд только на открытом сетевом экране с работающим агентом. Создание туннеля выполняется в официальном кабинете; неизвестные API не имитируются.
- Отдельные предпочтения LAN / direct / playit / manual для каждого профиля. Ручной режим принимает адрес уже настроенного другого провайдера, не запускает произвольные команды. Переключение режима меняет предпочтения, но не закрывает существующие туннели или правила: отключайте их отдельными кнопками.
- Локальные IPv4/IPv6 и шлюз читаются средствами Windows. Локальная проверка использует настоящий Minecraft Java status handshake, отдельно различая открытый TCP и корректный ответ Minecraft. Внешний IPv4 определяется по запросу через ipify. Для оценки CGNAT нужно сравнить его с WAN из панели роутера; частный LAN-адрес сам по себе не доказывает CGNAT.
- Отдельная внешняя проверка через `api.mcsrvstat.us` выполняется после согласия передать ему адрес сервера. Ответ может кэшироваться сервисом **до пяти минут**. Отрицательный результат не равен доказательству закрытого порта; окончательная проверка — Minecraft-клиент из другой сети. В CI не создаются публичные игровые туннели и не используется аккаунт владельца.
- Брандмауэр: просмотр, добавление и удаление только именованного правила `MineHost-<UUID>` для TCP-порта профиля. Область Private/Public и LocalSubnet/Any выбирается явно; изменения требуют отдельного согласия и Windows UAC. Общая политика брандмауэра не выключается. Чужие правила не заменяются.
- Опциональный UPnP через штатный Windows NATUPnP: отдельное согласие на проброс и удаление только совпадающей записи MineHost. UPnP зависит от роутера; если он недоступен, используйте ручной проброс или туннель. Правила и пробросы могут переживать закрытие MineHost — удаляйте их, когда доступ больше не нужен, в том числе перед удалением профиля.
- Собственный домен: инструкции A/AAAA и `_minecraft._tcp` SRV, проверка через системный DNS Windows, сравнение цели и порта SRV. Записи добавляются вручную у DNS-провайдера, без HTTP-прокси. Бесплатный адрес playit и внешние домены различаются: официальный внешний домен относится к Playit Premium, и SRV не обходит ограничения тарифа.

Порядок playit: скачать/выбрать агент → привязать в браузере → подтвердить привязку → настроить туннель в кабинете → запустить Minecraft → с отдельным согласием запустить агент → выбрать соответствующий туннель и сохранить настройки. Перед выходом остановите агент в сетевом разделе или настройках MineHost. «Агент работает» не подменяет проверку доступности самого Minecraft.

Источники интеграции: [официальный агент, тег v2.0.2](https://github.com/playit-cloud/playit-agent/tree/v2.0.2), [Playit Premium](https://playit.gg/support/playit-premium/), [Minecraft Status API](https://api.mcsrvstat.us/), [Windows NATUPnP](https://learn.microsoft.com/en-us/windows/win32/api/natupnp/nn-natupnp-istaticportmappingcollection).

## Обновление 0.4.0 — оставшиеся возможности этапа 2B

- **Forge и NeoForge**: официальные Maven-каталоги и installer JAR с SHA-1 провайдера; запуск установщика требует отдельного согласия и найденной/скачанной Java. Для Forge поддерживаются современные серверы Minecraft 1.17+, для NeoForge — доступные стабильные сборки из официального каталога. Подготовка проходит отдельно от мира; сервер запускается напрямую через Java и `win_args.txt`, без выполнения `run.bat`. Можно закрепить точную версию загрузчика при создании профиля, в том числе Fabric.
- **Каталог**: фильтр категории, подробное описание и до шести изображений галереи проекта Modrinth. Изображения проверяются по формату PNG/JPEG/WebP и размеру; HTML описания не исполняется.
- **Модпаки**: импорт Modrinth `.mrpack` с предварительным просмотром Minecraft/loader-зависимостей, серверных файлов и выбора optional-файлов. Клиентские файлы пропускаются; SHA-512 и размеры проверяются до замены. `server-overrides` накладываются после `overrides`. Требуется чистый профиль с установленным ядром и точным совпадением версий. Защищённые файлы MineHost и EULA не импортируются. Поддерживаются серверные каталоги mods/config/defaultconfigs/kubejs/scripts/datapacks/resourcepacks/resources/global_packs/patchouli_books/ftbquests/openloader и проверенный server.properties; другие пути отклоняются с объяснением.
- **История**: реальные стандартные сообщения join/leave записываются в SQLite с временем и сессией запуска; завершение Java отмечается отдельно. До 10 000 событий на профиль, страницы по 100. Старые логи задним числом не превращаются в события; изменённые плагинами/локализацией сообщения могут не распознаться.
- **Измерения**: копирование и перемещение Nether/End между остановленными профилями одной версии Minecraft, включая различие vanilla `DIM-1`/`DIM1` и отдельных папок Paper/Purpur. До замены создаются ZIP-копии обоих профилей. Заменённое измерение и перемещённый исходник сохраняются в `.minehost/dimension-trash`. Конверсия версий Minecraft и собственных измерений модов не выполняется.
- **Восстановление**: список локальных копий, импорт внешнего ZIP в совместимый профиль, просмотр состава, восстановление всего сервера или выбранного мира. Перед заменой автоматически создаётся копия текущего состояния; старая папка сохраняется для отката. Сохраняются текущий порт профиля, online-mode=true и отдельно данное согласие EULA. Современные копии содержат манифест версии/ядра; старые копии 0.3.x без манифеста требуют дополнительного внимания к совместимости.

Порядок для Forge/NeoForge: создайте профиль → найдите/скачайте Java в «Сервер и Java» → скачайте ядро и подтвердите выполнение официального установщика → примите EULA → запустите. Установка Java здесь нужна только Minecraft. Rust, Node.js и компиляция MineHost на пользовательском ПК не используются.

Для `.mrpack` допускаются HTTPS-загрузки с Modrinth CDN, GitHub, raw.githubusercontent.com и GitLab. Форматы CurseForge ZIP и сторонние bootstrap-скрипты не исполняются и не обходят ограничения платформ. Полная совместимость стороннего кода не гарантируется проверкой метаданных; сначала проверяйте новый модпак на отдельном профиле. Google Drive и планировщик добавлены в 0.6.0; CurseForge API остаётся в плане.

## Обновление 0.3.0

- **Файлы**: навигация по папкам профиля, создание папок и текстовых файлов, чтение и редактирование UTF-8 конфигураций до 1 МиБ, переименование и удаление текстовых файлов. Перед сохранением — резервная копия; если файл изменился после открытия, сохранение отклоняется до перечитывания. Изменения требуют остановки сервера. JAR и согласие EULA меняются через соответствующие разделы.
- **Миры**: выбор существующего мира для следующего запуска; подготовка нового мира с seed, генерацией, сложностью и режимом игры. Генерацию выполняет Minecraft при запуске. Импорт ZIP с `level.dat` в корне либо одной папке, экспорт и перемещение неактивного мира в корзину. Импорт не заменяет существующие папки и не активирует мир без отдельного выбора.
- **Игроки**: объединённый список из `usercache.json`, whitelist, OP и банов; UUID, запрос реального онлайн-списка командой `list`, whitelist/OP/ban/kick и сообщения `say` через консоль. Команды доступны работающему серверу. Ответ смотрите в консоли: успешная отправка не означает, что Minecraft уже выполнил действие. После ответа обновите списки.

Резервные конфигурации находятся в папке профиля `.minehost/file-backups`, удалённые файлы — в `.minehost/file-trash`, миры — в `.minehost/world-trash`. Корзины сохраняются для ручного восстановления при остановленном сервере через «Открыть папку»; автоматическое восстановление и очистка пока не добавлены. Экспорт мира требует нового имени ZIP вне каталога сервера и не заменяет имеющийся файл.

ZIP миров ограничены 32 ГиБ распакованных данных, 100 000 записей и глубиной 32. Ссылки, выход за каталог, коллизии имён Windows и исполняемые файлы запрещены. Это не конвертер версий миров: выбирайте совместимую версию Minecraft. Ванильные `DIM-1` и `DIM1` входят в архив основного мира; отдельные миры Nether/End Paper экспортируются отдельно. Отдельного переноса измерений между форматами ядер пока нет.

Онлайн-список — снимок ответа на `list` с временем запроса. При отсутствии стандартного ответа через 10 секунд показывается ошибка. Изменяющие формат команды плагины и локализованные ответы пока не разбираются. `usercache.json` — кэш известных игроков, а не полная история подключений. Автоматическая история, мониторинг, Forge/NeoForge и модпаки остаются в плане.

## Обновление 0.2.0

- Новые профили: **Vanilla, Paper, Purpur, Fabric**. Старые профили без поля ядра автоматически читаются как Paper. Существующие миры и настройки остаются на месте; смена ядра выполняется созданием отдельного профиля.
- Каталог **Modrinth**: поиск с сортировкой и страницами, фильтр по загрузчику и выбранной версии Minecraft, выбор стабильной версии дополнения, просмотр обязательных зависимостей перед подтверждением установки.
- Установленные дополнения: локальные JAR, отключение/включение после остановки сервера, проверка обновлений для файлов из Modrinth, удаление с переносом в `.minehost/addon-trash`. Перед заменой прежние файлы сохраняются в `.minehost/addon-backups`.
- Для Modrinth проверяется SHA-512, загрузка идёт во временную папку. Файлы заменяются только после скачивания и проверки всего плана. При сбое замены выполняется откат; незавершённые данные и резервные файлы сохраняются для восстановления.
- Fabric-моды проверяются по `fabric.mod.json`, стороне исполнения, версии Minecraft и установленному Fabric Loader. Paper/Purpur требуют `plugin.yml` или `paper-plugin.yml`; Forge-моды в эти профили не принимаются.

Установите обновление поверх предыдущей версии. Чтобы поставить моды или плагины, сначала скачайте выбранное ядро, затем остановите сервер и откройте «Моды и плагины». Подтвердите доверие к стороннему коду. Перед установкой из каталога просмотрите весь план: обязательные зависимости включены в него, необязательные автоматически не устанавливаются. SHA-проверенные неизменившиеся файлы повторно не скачиваются; шкала показывает обработанный объём файлов, включая проверку уже установленных.

Проверяются заявленные метаданные совместимости и явные конфликты Modrinth. Это не полная проверка совместимости кода или обратных зависимостей всех уже установленных модов. Ручные Paper-плагины проверяются по формату; их совместимость с конкретным Minecraft гарантировать нельзя. Неподдерживаемые варианты диапазонов Fabric возвращают ошибку вместо установки вслепую.

Официальные источники и проверки: Paper — SHA-256; Vanilla/Mojang — SHA-1; Purpur API — MD5 поверх HTTPS. Эти алгоритмы отражают данные провайдера, а не одинаковую криптографическую стойкость. Fabric Meta не публикует отдельную контрольную сумму сгенерированного launcher: используются официальный HTTPS-адрес и проверка структуры JAR. Fabric хранится как `fabric-launcher.jar`, чтобы не конфликтовать с загружаемым им vanilla `server.jar`. Зависимости Fabric и Minecraft догружаются самим launcher при первом запуске с отдельными логами в консоли.

## Установка

Скачайте `MineHost_*_x64-setup.exe` из [Releases](https://github.com/Frish07/MineHost/releases). Если релиза ещё нет, приложение ещё не опубликовано. Наличие исходников или зелёного workflow подготовки зависимостей **не означает успешную сборку приложения**.

Сравните SHA-256 с `SHA256SUMS.txt` из того же релиза. Установщик предназначен для текущего пользователя. Приложение пока не подписано сертификатом издателя. MineHost использует WebView2; Windows 11 обычно уже включает его, иначе установщик предложит официальный runtime Microsoft.

**Rust, Cargo, Node.js, npm, Tauri CLI, Visual Studio и JDK для сборки на компьютере пользователя не нужны. Ничего из этого MineHost не устанавливает.** Исполняемый файл `MineHost-windows-x64.exe` можно запускать без установщика при наличии WebView2; данные всё равно хранятся в пользовательском каталоге, а не рядом с EXE.

## Первый сервер

1. Создайте сервер, выберите ядро, загрузите список версий Minecraft. Укажите отдельный порт и RAM.
2. В «Сервер и Java» скачайте выбранное серверное ПО. При отсутствии подходящей стабильной сборки операция завершится понятной ошибкой.
3. Прочитайте Minecraft EULA по указанному адресу и самостоятельно подтвердите согласие.
4. Нажмите «Найти Java» либо укажите полный путь к `java.exe`. Можно скачать приватный Temurin **JRE**, подтвердив загрузку. Он используется только Minecraft, не меняет PATH, JAVA_HOME или системную Java. В папке runtime находятся его лицензии.
5. Запустите сервер. В консоли дождитесь сообщения Minecraft `Done`. Это может занять время: Paper сам загружает необходимые компоненты при первом запуске.
6. Подключайтесь с этого ПК к `127.0.0.1:порт`. Для друзей в LAN используйте IPv4 компьютера. Доступ из интернета пока настраивается вручную.
7. Для плагина остановите сервер, подтвердите риск стороннего кода и выберите один или несколько JAR либо перетащите их в окно. Проверяются ZIP-структура и наличие `plugin.yml`/`paper-plugin.yml`; это не аудит кода и не гарантия совместимости версии.
8. Останавливайте кнопкой «Остановить»: отправляется `stop`, принудительного завершения нет. Состояние изменится только после выхода Java. Не завершайте приложение через Диспетчер задач во время записи мира.

Доступны несколько одновременно работающих профилей, SQLite, уникальные порты, ограничение суммы максимальных heap Java в 12 GiB, ограниченный буфер логов, поиск и история команд, редактор properties с `.bak`, локальные ZIP-копии остановленных серверов. 12 GiB — лимит heap, а не измерение физической RAM; Java использует дополнительную память. Удаление перемещает папку в `trash` после ввода точного имени.

## Только облачная сборка

Исходники редактируются без локальной сборки. Все команды Rust/npm выполняются **только на `windows-latest` в GitHub Actions**. Подробно: [облачная сборка](docs/CLOUD_BUILD.md).

Первый push в `main` запускает **Prepare cloud dependencies**. Runner формирует настоящие `package-lock.json` и `src-tauri/Cargo.lock`, форматирует Rust, коммитит результат и явно запускает **Build Windows x64**. Первый параллельный Build без lock-файлов может завершиться с инструкцией дождаться подготовки; повторный Build работает уже с зафиксированными файлами. В обычных сборках используются только `npm ci` и Cargo `--locked`.

Build проверяет форматирование, Clippy, тесты Rust, TypeScript; собирает frontend, backend и NSIS-установщик. Только после этого создаётся artifact `MineHost-windows-x64` с EXE, установщиком и SHA-256. Успех необходимо проверять именно у **Build Windows x64**, а не только у Prepare.

Тег версии приложения (например, `v0.3.0`) запускает отдельный release workflow с повторением всех проверок, проверкой версии и публикацией GitHub Release. Тег нужно ставить **после** появления закоммиченных lock-файлов и успешного Build. Без локального Git это делает workflow **Create version tag** в Actions. Начальные версии публикуются с отметкой Pre-release; готовность всех этапов исходного задания не заявляется.

## Code signing policy

Бесплатная подпись через SignPath Foundation подготовлена, но **одобрение проекта ещё не получено, текущие релизы не подписаны**. После подключения подписываются приложение и установщик в GitHub Actions; каждое подписание требует подтверждения владельца в SignPath. Включённый режим подписи запрещает публикацию при ошибке или отсутствии подписи. [Code signing policy](https://github.com/Frish07/MineHost/blob/main/CODE_SIGNING_POLICY.md), [настройка](docs/CODE_SIGNING.md), [privacy policy](https://github.com/Frish07/MineHost/blob/main/PRIVACY.md).

## Данные и ограничения

Данные: `%LOCALAPPDATA%\dev.frish07.minehost\`: `servers/<UUID>`, `backups`, `cache`, `logs`, `config/minehost.sqlite`, `runtimes`, `trash`. Системные каталоги сервера не используются. Резервные копии создаются только при остановленном сервере. Восстановление всего профиля или мира доступно в GUI с защитной копией.

Остаются в плане: CurseForge при разрешённом API/ключе, подпись, согласованные копии работающего сервера, форма server.properties и usability QA. Реализованные этапы и границы проверки: [ROADMAP](docs/ROADMAP.md).

Официальные источники: [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/), [Paper Downloads API v3](https://docs.papermc.io/misc/downloads-service/), [Adoptium API](https://api.adoptium.net/). MineHost не связан с Mojang, Microsoft, Aternos, PaperMC или Eclipse Adoptium.
